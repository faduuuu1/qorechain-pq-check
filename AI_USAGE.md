# AI usage

This project was built in a working session with Claude (Anthropic). This file
records what the AI did, what it got wrong, and what the human decided, because
the award asks for the workflow and not just the output.

## The workflow

The pattern was **read the source of truth first, then write code**. Before any
line of `scripts/check.ts` was written, the SDK's own type definitions were read
out of `node_modules`:

- `fetchPqcStatus(opts: { rest, address, fetch? }) => Promise<PqcStatus>` and the
  `PqcStatus` fields (`registered`, `algorithmId?`, `pubkey?`, `possessionProven?`)
- `evmWindowStatus(opts: EvmWindowStatusOptions) => Promise<EvmWindow>` and the
  `EvmWindow` fields, plus `toQorAddress` / `toEvmAddress`
- the `EvmWindowRejection` union (`no-window` | `exhausted` | `invalid` |
  `no-pqc-key`), which is where the tool's verdict vocabulary comes from

No API signature in this repo was guessed. The verdict logic is a direct reading
of the SDK's own failure taxonomy.

The doc comment on `fetchPqcStatus` is what produced the "unknown is not no"
rule: the SDK deliberately throws rather than returning "not registered" when an
answer is unreadable, and the tool preserves that rather than flattening it into
a false negative. That design point came from reading the library, not from a
prompt.

## What the AI produced

- the scaffold command and template choice (`evm-solidity`, testnet preset)
- `scripts/check.ts` in full (187 lines)
- `scripts/window.ts` brought in from the `hardhat` template to close a gap the
  `evm-solidity` template's own README flags: that template cannot open the EVM
  authorisation window
- the `.gitignore` the template ships without - the scaffolded `.env` holds a
  placeholder private key and would otherwise have been committable
- `src/readiness.ts` - the pure logic extracted from the script so it could
  be tested at all; `scripts/check.ts` was rewritten to import it
- `test/readiness.test.ts` - 14 cases on Node 24’s built-in runner, no new
  dependency
- this file and `README.md`

## What the AI got wrong

- it first scaffolded `evm-solidity` without noticing that template has no
  window helper; the gap was caught reading the template README afterwards
- `npm run typecheck` failed with a path error under Git Bash; the compiler had
  to be invoked directly. The script is left as-is since it works elsewhere

## What the human decided

- the category (Quantum Pass) and that the project should be a checker rather
  than a game or a bot
- which account to test against
- registration, the QoreX wallet, the testnet address and every key: no
  credential in this project was generated by the AI, and the `.env` in the repo
  still holds the scaffolder's all-zero placeholder

## Verification

The tool was not declared working until it had been run against live QoreChain
testnet and returned a correct verdict for a real address, with `tsc --noEmit`
passing. The README's sample output is a real run, not an illustration.
